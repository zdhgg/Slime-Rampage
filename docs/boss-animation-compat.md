## 只读接口

`boss.attackMove` 返回冻结的 `{ id, name }`，名称来自既有通用配置、章节配置或边防官 MOVES 表。边防官 `step` 使用既有跨步状态文案。`combatInfo` 和蓄力状态文案使用同一来源。现有剧情对白为静态事件文本，没有新增招式名称映射。

`boss.attackPresentation` 返回冻结的浅快照：

| 字段 | 契约 |
| --- | --- |
| `id` | 当前招式 ID；idle、phase、dead 时为 null |
| `name` | 当前/最后招式名称，收势期间保持稳定；无攻击时可作提示名称 |
| `stage` | idle / telegraph / dash / step / chain / recover / phase / dead |
| `progress` | 当前阶段 0..1 的有限值；瞬时结算没有独立、可推进的表现阶段 |
| `clock` | 初始化为 0 的局部动画秒钟，仅在存活且可行动的更新中推进 |
| `attackRemaining` | 已有释放表现剩余秒数；目前只有边防官设置 .48 秒 |

快照不暴露 `_cast`、`_fx` 或技能几何引用，不选择目标、不移动、不结算伤害、不推进时间。渲染继续使用原几何和资源；仅原有阴影渐变缓存可在渲染时建立。

冻结保留攻击预警、进度和命中标记，动画时钟及释放计时暂停；恢复后继续同一段攻击，冲锋不会再次命中。边防官 `_fx` 沿用原有真实时间衰减。通用 Boss 的破绽计时仍遵循原逻辑，不统一成边防官规则。

`cancelAttack()` 清除攻击计时、命中标记、连段、技能数据及边防官预警/释放效果，并释放协同施法占用；不修改攻击冷却，不决定后续 AI。通用 Boss / 章节 Boss 转阶段调用时保留既有破绽承伤计时，避免兼容清理改变实际承伤。死亡也保留原 `vulnerableTimer` 供编队破绽击杀结算读取，`combatInfo.vulnerable` 在死亡后为 false，死者不绘制。先失活再释放施法占用，避免死亡触发额外奥术接力。重置通过销毁旧实例完成，不复用旧对象。

- `node verify-boss-animation.mjs`：104 个攻击/生命周期场景，13 个重置场景、20 个动画时钟场景及四种帧率下冲锋命中后冻结/恢复检查通过。覆盖通用、章节及边防官路径；15/30/60/120 FPS；两个阶段；零/负/非有限 dt；冻结恢复、转阶段、直接死亡、重置、取消；每段直接伤害事件至多一次；伤害仅在既有 telegraph 结束或 dash 中发生；重复渲染不改变战斗状态。

- `node verify-border-warden.mjs`：原有 16 组机制与 18 个真实武器场景通过。
- `node verify-expedition-bosses.mjs`：原有 5 组章节首领断言通过。
- `node verify-boss-squads.mjs`：原有 12 组编队断言通过，包括破绽击杀截断血誓及奥术接力。

## 后续美术接入与边界

后续高细节厚涂幻想风角色可在表现层读取统一招式 ID、阶段、进度和局部秒钟选择姿态、帧和过渡。未来如需动作骨骼或更细释放阶段，应追加只读数据，不让渲染回写战斗字段；当前接口不承担新动画调度框架职责。

本轮没有制作或迁移美术。自动测试使用画布桩验证数值与渲染副作用，未做真实浏览器的像素或美术验收；基线轨迹不是全部玩家移动路线的穷举，边防官原有绕圈及变向测试提供额外覆盖。弹幕生成参数和事件已对比，其后续碰撞沿用现有完整测试。净巢司祭、封印主教、讨伐统帅的既有伤害范围未修订。启动/资源加载未改变，因此未额外执行启动测试。
