# 六种史莱姆当前美术方案

> 当前生效版本：`current-r2`（概念对比板"方案 A"）。这份文档是后续角色造型、立绘和战斗表现的唯一入口。
> r1（兜帽/斗篷/缓冲翼）与 Route A（金币/水弹/宝宝）草案均已被替换，不再作为设计依据。

## 为什么重做

r1 / Route A 的问题：五个角色共用几乎同一组蛋形锚点，身份只靠头顶几像素的小卷尖；识别物画在体内被果冻遮罩盖住；元素与暗影同为紫色；六张脸共用一套眼睑参数；多层玻璃高光与扁平矢量的世界风格冲突。

## 统一规则

- 顺序固定：**轮廓 → 外部身份锚点 → 表情 → 材质**。不能用换色代替轮廓差异。
- 材质为"扁平+"三色阶：暗部 / 底色 / 亮部 + 一个高光 + 同色系描边。描边按屏幕像素保持恒定（约 2px @ r26，约 3px @ 立绘）。
- `r26`（Arena 逻辑半径，1:1 CSS 像素）是最低验收尺寸。r < 40 时自动切到战斗 LOD：隐藏体内小气泡、刻痕等细节，必要时加粗锚点（如弹射喷管）。
- 六个角色在色相和明度上同时拉开：绿、红、蓝、珍珠白（随元素染色）、墨黑、玫瑰粉。
- UI 强调色、身体底色和身份描述统一登记在 `src/game/SlimeFamilyArt.js`（`color` 为深色 UI 上可读的强调色，`body` 为世界内身体底色）。
- 正式绘制只从 `src/game/slime-art/` 读取：`slime-painter.js`（材质与五官工具）+ `slime-cast.js`（六个角色、姿态表）。`test-support` 和临时看板不能成为运行时依赖。

## 运行时接入

- `Player.render`：`SlimeFamilyArtRenderer` 的 body → 进化/元素叠层 → face；剪影（进化着色、蓄力描边、受击红闪）走 `paintSlimeFamilySilhouette`。元素史莱姆把 `player.elements` 传给美术层，并且不再叠加旧的雷角/熔岩甲/毒泡配件。
- 选择页 `SlimeFamilyPortrait.vue`：同一套 cast，`element` 属性显示所选起始元素。
- Runner 主角、暗影分身/闪避残影同样使用当前 cast。
- 暴食咬击口器与共生弹体颜色已同步到新配色。
- 旧渲染器（`SlimeRenderer.js`、`SlimeAppearance.js`、`ArenaOriginSlimeArt.js`）已删除，`verify-art-v1.mjs` 会断言它们不再存在，并对六角色 × 全姿态 × r26/r100 × 全部表情标志做绘制冒烟。

## 动态表现（精修）

- **面部朝向**：开火/咬击时脸转向目标，移动时转向前进方向，静止回中；`Player` 按游戏时间平滑（`lookX/lookY`，脸整体偏移约 5 单位）。
- **冲刺表情**：移动较快时进入专注（眼睑向鼻梁倾斜）；低血量为疲惫（眼睑外垂，暴食嘴张幅减半）。
- **暴食**：待机下颌缓慢咀嚼，嘴角口水周期性成形、拉长、滴落；咬击时仍由 GluttonBiteVisual 的口器接管。
- **弹射**：每次齐射读取 `WeaponSystem.muzzleKick`，三根炮管沿轴后坐，炮口闪光。
- **元素**：元素球沿慢速椭圆漂移；帽尖在第一元素色中闪烁；法术释放（`castPulse`）时元素球放大发光、身体染色加深；第二元素未解锁时是缓慢呼吸的虚线空槽。
- **暗影**：影尾双频正弦摆动，剪影与受击红闪跟随同一尾姿；尾尖有淡紫余烬，地面墨丝各自漂移，细眼光晕脉动。
- **共生**：三颗圆芽各自错相位上下浮动，受击时下压。

## 后续设计的硬门槛

新角色或新姿态进入主分支前，需要同时满足：

- 与六个当前角色并排时，黑剪影在 r26 下不依赖颜色即可区分；
- 灰度下保持亮 / 中 / 暗档位，不全部挤在中灰；
- 放入真实 Arena 截图（1:1，r26）后一眼可找到；
- 待机、移动、蓄力、释放、受击只改变软体形变和锚点状态，不改角色身份；
- 颜色、文案和锚点登记到 `SlimeFamilyArt.js`，不在组件内重复定义；
- 通过 `npm run build` 与 `npm test`。
