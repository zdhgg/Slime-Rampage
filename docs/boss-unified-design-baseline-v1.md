# Boss统一设计基准 V1

状态：待审阅设计稿。日期：2026-10-29。适用：《史莱姆大暴走》主战场的远征、限时与无尽模式；塔防仅共享视觉原则，不共用战斗规则。

本基准的方向是：**保留已有可用机制，以身份、持械和动作解释攻击；先修预警与判定、接口与动画基础，再逐名完善表现。** 不把十二名首领全部改为近战，不以增加技能数量制造差异，不把候选素材或通过脚本测试等同于完成设计验收。

本轮仅编写设计文档；以下所有建议均尚未实施，不代表获准修改玩法或素材。

## 2. Boss 系统现状与核心问题

### 2.1 现有架构与复用边界

| 对象 | 正式实现 | 与远征的关系及边界 |
| --- | --- | --- |
| 普通三职业 Boss | 骑士王加洛特：贴身普攻与冲锋；大法师梅林：扇射、环爆及援军；弓王罗宾：扇射与箭雨 | 共用 Boss 的状态、受击、阶段和破绽；是低成本职业教学原型，不能都换成章节专属身份 |
| 复合 Boss | `boss-final` 终审勇者阿尔凯恩、`boss-expedition` 通用讨伐统帅；轮换骑士、法师、弓手强招，普通攻击走远程路径 | “复合”指一个实体轮换攻击模式；不是多 Boss 编队。当前通用剑盾外观不足以解释法术和射击 |
| 远征十一人 | ExpeditionBoss 继承 Boss，按 archetype 复用职业普攻，替换章节强招 | 终章雷欧尼斯也在此路径，且明确 `isCompositeBoss = false`；不能因同名统帅而当作通用复合 Boss |
| 边防官 | EnemyManager 按 encounter.id 单独创建 BorderWarden，继承 ExpeditionBoss 但覆盖 update 与行动循环 | 已有完整有界追击和枪盾连段；不能用候选旧 ExpeditionBoss 的边防官分支覆盖 |
| Boss 编队 | EnemyManager 管分组、补位、共享强招令牌和编队规则 | 后续动作适配必须保留令牌、死亡清理、破阵与奖励流程，不让多个全场危险预警无序叠加 |
| 塔防 Boss | 独立 TowerDefenseGameplay/Renderer，章节阶段与六类小首领特性 | 可统一轮廓和预警语义；不能移植主战场近战距离、角色命中或 BorderWarden AI |
| 跑酷 | 当前 RunnerDirector 无独立 Boss 遭遇入口 | 本轮不新增 Boss 系统 |

除边防官外，章节首领继承 75% 血量召两名骑士、25% 血量追加加速/攻频的阈值行为；半血进入二阶段，ExpeditionBoss 再加速并把强招变为两至三段。多数章节强招直接伤害从一阶段 2 变为二阶段 3，具体投射物另走自身规则。**这些是现状，不全部确认为未来标准**：护卫、加速与密度应逐名审查，避免十二场同一套叠压。

边防官覆盖了上述护卫和残血加速钩子；半血用新连段区分，伤害固定 2，经 outgoingDamage 结算，不新增接触伤害。

### 2.2 需要解决的问题

| 问题 | 具体证据与影响 | 处理方向 |
| --- | --- | --- |
| 身份轮廓雷同 | 主线 Boss 仅三套 `boss_knight/mage/archer` 程序精灵；骑士、法师、弓手同样戴王冠，司祭、司库、主教难靠轮廓区分 | 保留共同装甲语言，以头部、主装备、体态形成差异；王冠只留给真正王级身份 |
| 武器不能解释攻击 | 边防官拿剑却枪刺；盾将放箭墙；圣骑远程点名十字加法球；近卫横斩再放箭；终章持剑下棋放弹 | 四名近战优先回归武器逻辑；法师/指挥类保留魔法，但明确施法媒介和源头 |
| 身体动作落后于地面预警 | 4 个循环帧加 1 个攻击帧；身体主要左右翻转，攻击帧受 attackCd/dash 驱动；边防官盾扫、枪刺并未驱动专属武器动作 | 用已有状态和少量姿态表达蓄力、出手、收势，避免“地面已经打完，手还没动” |
| 动画字段与接口断层 | BorderWarden 更新 `_animClock/_attackAnim`，主线 Boss 构造器未初始化；候选动作读 `_meleeCast/_meleeFX`，边防官实际用 `_cast/_fx` | 先补有限值、时钟及只读表现适配，再迁入动画代码 |
| 判定与预警覆盖范围不一致 | 主教只画本体周围四块 360 方格，判定却按世界象限；棋局只画目标附近 9×9 格，判定按世界棋盘奇偶；净火外圈之外也直接伤害，外部危险标记不足 | 保留象限/棋格/安全环概念，先定义可见危险边界；所有直接区域伤害只在已明确预警的范围结算 |
| 把弹道线当成瞬时区域 | 围猎线只是箭的路线；双生回响的圆主要是发射点；原圣骑预警十字四角超出其 360 径向判定 | 区分直接伤害面、投射物路线和召唤提示；共享几何，不能默认现有绘制已精确 |
| 控制与削弱结算不统一 | 边防官读取多种减速、地形及 outgoingDamage；通用 Boss 移动主要读取 slow，多个直接 p.hit/弹幕路径未统一套用削弱 | 后续统一状态效果入口，先测再改；不以“Boss免控”掩盖角色功能失效 |
| 候选美术风格与主线跨度大 | 主线偏平面、棱角、装甲与发光装置；枪盾 PNG 是高细节、苔藓金属、厚涂幻想风 | 先定共同风格和体量，再验候选 PNG；不能因存在文件就强制采用 |

这些几何和结算结论来自静态代码复核；不等于已完成全部视口、地图边角和组合场景的运行时验证。上轮主线回归、构建与浏览器通过，说明代码可运行，不证明上述设计与视觉问题不存在。

## 3. 统一设计原则

### 3.1 世界观与视觉定位

保留“史莱姆为自保反攻王国、逐步揭开讨伐和封印真相”的主线。名字、圣物、军阶与亡魂叙事继续成立；装备可以有机械结构和能量核心，不需要追加一套赛博历史来解释所有角色。

**建议的 V1 默认风格：以现有程序化装甲为底，采用轮廓清楚、细节克制的奇幻与机械混合风格。** 边境是磨损与植被，王城是规整盾甲与军徽，圣殿是炭化纹与圣印，王陵是残破甲壳与魂光，封印区是几何符印。材质服务身份，不把所有首领都做成巨大金甲王者。最终风格选择列入第 8 节待确认。

每名首领至少有两项非颜色、非缩放的识别特征，来自头部轮廓、主武器、肩背装具、站姿或移动方式。法杖类可共享骨架，不得所有人都只有换色法杖加同一王冠。体型可以不同，但图形放大不改变 radius 和命中范围；脚底锚点、阴影与身体中心要稳定。

### 3.2 武器与战斗方式

每名首领以一个主要压力来源和一个已有核心机制为中心。近战四人的差异是“枪盾追击、重盾防线、战锤重砸、长柄横斩”，不再各自增加一套不相关弹幕。远程、召唤和指挥首领以自己的媒介解释攻击，不要求上前肉搏。

近战攻击从身体或武器可见位置产生，先有限接近、再锁向蓄力、执行、收势。方向一旦承诺，不允许视觉定向后暗中追踪。武器攻击之外可有与身份相关的短程能量冲击，但必须有明确源头、边界和延迟；不能把原远程弹换个颜色就称为近战。

本稿**不默认新增盾牌百分比减伤、精准格挡、部位破坏或背刺倍率**。盾将的防御特色先用守位姿态、攻击方向和出手后侧翼机会实现。是否需要额外防御规则，须由试玩证明现有手段不足。

### 3.3 最小动作要求

| 动作 | 最低可交付表现 | 与逻辑的约束 |
| --- | --- | --- |
| 待机 | 呼吸/重心和持械姿态；武器与身体不漂移 | 不循环攻击格；停止行动时仍可辨身份 |
| 移动 | 现有循环帧或两步姿态、脚底锚点连续 | 位移来自实体 update，渲染不能推动碰撞体 |
| 转向 | 头/躯干与武器向锁定方向调整 | 左右翻转可保留；全角度攻击须有武器或方向标记补足，不能只把角色整体转平 |
| 蓄力 | 武器后撤、举盾、举锤或装置充能 | 使用同一招式的锁定方向与计时；没有伤害，不能追着玩家改预警 |
| 出手 | 枪尖前送、盾缘横扫、锤头下砸、弩口射击 | 身体与武器在实际生效时刻有接触/释放姿态；特效不能滞后到收势才起动 |
| 命中/挥空 | 命中短闪或碎屑；挥空仍完整出手 | 伤害只由战斗执行，命中特效不得再次扣血；残影留在实际施放位置 |
| 收势 | 武器回收、盾落下、锤拔起或施法器熄火 | 连段间隙与整套结束有不同姿态；保留可近身输出窗口 |
| 受击 | 短闪或小幅弹性后坐 | 普通受击不自动打断全部技能，不靠强烈抖动掩盖预警 |
| 转阶段 | 明显但简短的姿态/装置变化 | 清除未执行旧招，取消旧预警与危险事件；新阶段每段仍有预警，不新增无预警阶段爆炸 |
| 退场 | 解除危险预警，简短消散/倒下 | 停止未执行伤害、释放令牌；已发弹幕按原规则明确处理，不被渲染悄悄改变 |

可优先采用共享身体循环、少量武器姿态、程序插值和短特效。V1 不要求八方向全套序列帧；关键是能看出“谁在攻击、向哪里、何时生效、何时能反击”。单一突刺格不能覆盖盾扫、战锤、冲锋全部动作。

### 3.4 预警与伤害的共同语言

1. 危险填充面表示会直接结算伤害；线路箭头表示将飞行的投射物；虚线小圈表示召唤或传送落点。保留职业点缀色，危险语义不能随 Boss 变化；轮廓和纹理辅助识别，不能只靠红绿差异。
2. 绘制与直接命中读取同一个形状、位置、角度和边界策略。玩家中心/碰撞圆两种口径不混用；边防官现为玩家中心，先保留并明确测试。装饰光晕可以超出，但不能像危险边界。
3. 投射物路线预警不承诺箭已瞬间填满整条线；释放后由真实子弹位置与碰撞半径结算。召唤标记不附加未声明伤害。
4. 大范围机制先确定有限、清楚显示的作用范围。主教和棋局建议优先把判定裁进实际绘出的区域；若坚持全场作用，必须完整展示当前视口危险与可达安全区，另行验收，不能保留局部画面配无限判定。
5. 蓄力足够让基础移速 340 的角色通过正常移动到达安全位置；最短可走路径要考虑障碍、边界与玩家半径。不能只以直线距离/速度证明可躲。若安全区不可达，施放前调整落点、方向或选招，不能施放后瞬移玩家。
6. Boss 预警、玩家元素场、伙伴特效、对白和伤害数字叠加时，危险轮廓仍应清楚。装饰降低透明度或数量，预警保留可读层；对白不能是唯一预警。

### 3.5 六种史莱姆的兼容基线

| 角色 | 正式战斗特点 | Boss 设计必须支持的应对 |
| --- | --- | --- |
| 原生黏液 | 自动飞弹、自由专精、元素权限，主动震荡解围 | 不按角色 ID 加免疫；普通走位可解招，成长与融合能缩短战斗 |
| 暴食 | 近身咬击，身体外延 48；重咬外延 68；靠真实首领普攻命中积累猎食点 | 对半径 36 Boss，基础中心距约 110/130 可命中；收势允许走近、至少起手并完成一次普攻，不能靠触体暗伤阻断整个资源循环 |
| 暗影 | 外延 72 近战影刃、影袭与暴击分身，存在概率闪避 | 侧后方和收势可以进攻；影袭可提高效率，但每招都能用基础移动躲，不能要求赌闪避 |
| 弹射 | 齐射与高速飞弹，疾射短时加速 | 留弹缝、锁向后允许改道；用有限接近与区域选择制造压力，不用全场瞬中惩罚远程 |
| 元素 | 火、水/冰、雷、毒四起始法术，双元素融合、法术盾；毒雾和延迟伤害需要停留时间 | 近战窗口外也有中距离持续输出机会；不因 Boss 长时间传送使毒雾近乎失效；减速/削弱效果结算有据可查 |
| 共生 | 本体飞弹伤害 55%；四种伙伴，每种一只、独立生命；主动共生鼓舞 | 限制连续跨屏位移；伙伴追上与鼓舞期间有输出时间；不能默认护卫嘲讽可吸走 Boss 强招 |

这些距离用于检查基础构筑的可接近性，不是把全部攻击、索敌和投射物寿命折成一个“统一射程”。元素专属法术和 origin 的旧元素路径也不能混测为同一套实现。

保持移动、自动输出和单主动技能的现有割草定位；不新增通用翻滚、耐力、完美防御或复杂按键连段。玩家成长后更快击杀、跳过部分循环属于合理收益，不强制锁血播放全套。二阶段优先改变已有招的组合、方向或区域选择，整套越长，结束后可利用的停留越充分；不默认缩预警、加速、加伤三者一起叠。

## 4. 十二名远征 Boss 逐项设计基准

下表优先级是实施顺序，不是难度或剧情地位：P0 为公平性/基础接口阻断，P1 为主要身份与近战适配，P2 为已有机制的辨识度完善。共享 P0 必须先做；某人的 P0 修复不要求同时完成其 P2 美术。

### 4.1 总览表

| Boss ID 与名称 | 身份、建议核心装备 | 核心战斗风格 | 保留与主要调整 | 优先级 |

## 5. 技术适配要求

### 5.1 保留架构，补最小接缝

继续使用 Boss → ExpeditionBoss → BorderWarden 和 EnemyManager 的创建分流。四名近战不等于四个新引擎：其余三人先在 ExpeditionBoss 的现有机制路径使用小型几何/动作描述；只有行动循环确实不同且条件分支难维护时，再讨论独立子类。

| 关注点 | 正式/候选事实 | 后续最小适配要求（尚未实现） |
| --- | --- | --- |
| 身份与资源映射 | 正式按 type 选三职业图；候选按 stageBossId 映射五种图 | stageBossId 优先用于视觉选择，type 继续用于既有职业/掉落；不能为换皮改 archetype，避免连带改变普攻、血量与奖励 |
| 招式身份与名称 | RunRules 有特殊技总称，边防官 MOVES 自带实际招名 | id 保持稳定；总称、当前招名、阶段名分别使用，HUD、状态、对白引用同一当前招式描述，避免多份自由字符串漂移 |
| 动画初始化 | 主线 BorderWarden 存在 undefined→NaN；候选 Boss 已补字段 | 构造/重置明确初始化所有实际读取字段；攻击进度以各招真实持续时间计算，不能都除以 0.48；只在负责的 update 路径推进一次 |
| 三种攻击形态 | 普通 Boss 的 lockedAngle/target；边防官 _cast/_fx；候选 _meleeCast/_meleeFX | 如需共享渲染，可加一个只读 `getAttackPresentation()` 小方法（建议名），各类映射当前招 ID、表现阶段、原点、角度、进度和已有形状引用；不要求战斗状态全部重写成新格式 |
| 形状与时序 | 边防官形状已共享；其他区域多为分别手写 | 新近战共享 shape/contains/path；其他机制逐个修配对几何。render 不能移动 Boss、选目标、扣血或推进战斗时钟 |

| 状态效果 | Boss、BorderWarden 对减速/冻结和收势计时口径存在差异 | 明确哪些计时随冻结暂停；攻击、地面进度与武器动作一致，整套收势不能在冻结中被悄悄耗尽。显示时钟可继续呼吸，但不能伪造出手 |
| 阶段与终止 | 边防官有独立阶段/连段字段；基类仍用 _chainStep/_chainTotal | 阶段变化、死亡、重置分别取消未执行 cast/残影/命中标记并正确释放令牌；不强迫两套 AI 共用同一内部连段数组 |

### 5.2 素材、回退与风格验收

正式 AssetManager 启动时烘焙职业精灵，`char_<role>_<frame>` 使用 0–3 循环与 4 攻击；Boss 使用这些程序图。候选新增五种 role 和四格 PNG 异步加载，drawExternalFrame 假定四个等宽格。**这些加载和映射能力都还未进入 main。**

建议的迁移顺序是：对应职业的程序化独立轮廓先可用 → 经确认的外部图再作为可选增强。资源缺失、未加载、解码失败、尺寸不符或帧不存在时，优先退回该 Boss 的程序轮廓，再退回三职业图；任何回退都不得改变攻击范围、时间、伤害或碰撞半径。

外部图至少验证帧数/尺寸、透明边缘、脚底锚点、角色中心、武器可见范围与四周裁切。现有枪盾 PNG 宽 2161，并非四整格宽度的整数倍，不能直接把“除以四能绘制”当作严格帧布局已验收。不得把步行格、攻击格按随意索引混用；盾扫与冲锋缺帧时使用程序武器姿态，不能谎称已有专属帧。

程序图与外部图须在同一背景、同一实际游戏尺寸下并排评审：轮廓、线条、光照、材质密度、阴影、亮度及特效饱和度协调，再决定是否启用。缩放和后坐只影响画面；禁止直接放大 radius 追随美术，禁止导入大图后顺手改 Boss 强度。

### 5.3 普通、复合与章节的同步边界

- 普通三职业保留教学价值，先修普攻动作与提示，不照搬边防官高压连段。新的通用动画初始化与受击表现可共享，专属持械按身份映射。
- 复合 Boss 可以保留三职业轮换，但每轮用武器附属装置/符印点亮解释当前模式；不要求造三套完整身体。不能把远征终章的军旗皮肤无条件映射到终审勇者。
- 分别测试 `boss-final`、通用 `boss-expedition` 与 `court_commander` 的创建、普攻、特殊技、阶段和对白；它们不是同一类/同一技能表。
- 塔防沿用各自 Renderer 的动作和特性；如圣城压制机甲仍映射剑盾骑士，列为后续独立视觉任务，不在本轮近战迁移中顺手重做。

| EnemyBullet | Boss 弹增加拖尾/外环，普通弹另保留 | 远程法术/箭矢的适度区分 | 不能给改成近战的三人保留装饰性假弹；特效不能掩盖危险轮廓或显著虚增弹径 |
| MapFeatureManager | 边境黏液池材质修改 | 留作地图视觉独立任务 | 不属于 Boss 必要迁移，不与本轮候选美术一起合入；不淡化真实减速边界到无法辨识 |
| verify-expedition-bosses | 候选扩展到四近战及旧边防官更新链 | 迁移其余三人的命中/挥空/零弹幕断言 | 保留 main 对 BorderWarden 的分流验证；不可用旧测试替换新契约 |

上轮隔离验证的准确含义：原 `52da6fe + 候选文件` 的远征专项 7 组通过；同批文件直接覆盖 `947fdbc` 的隔离副本后，旧脚本出现 `chain != recover`，后续还依赖 `_meleeCast`；主线边防官专项在叠加副本里仍通过。**因此候选具备可复用部分，但整包并不兼容新基线。** 本轮未重跑或迁移这些候选。

后续每次只迁移一种成果，先在干净的最新 main 分支抽取小补丁，保留来源说明、差异与验收证据。先做不改变玩法的初始化/适配和外形，再用独立提交修改攻击机制；原工作区一直保留，直到用户确认候选已逐项取舍。

## 7. 分阶段开发与验收

### 7.1 实施顺序

| 阶段 | 内容与原因 | 完成条件 |
| --- | --- | --- |
| A 基础兼容与公平性 | 修动画有限值、各类更新路径、当前招名/状态、共享表现适配；并优先修主教/棋局/净火的预警边界。几何危险比造型优先，不等整套美术完成 | 三创建路径不串招；冻结/转阶段/死亡无残留；未警告区域没有直接伤害；主线边防官机制保持 |
| B 造型小批迁移 | 用户确认风格后迁入五类程序轮廓和回退；位图作为单独选择。先轮廓后精细动作，避免做完动作再换武器 | 实际尺寸能以轮廓和主装备区分，资源失败仍有完整可读角色；main 玩法参数不变 |
| C 边防官表现闭环 | 对接已有追击 AI 的盾扫/枪刺/冲锋、跨步、收势、名字与对白；作为技术样板 | 16+18 专项保留；真实 Canvas 中身体、武器、预警和结算同步，六角色均能利用窗口 |
| D 三名近战逐个调整 | 盾将→灰烬圣骑→近卫；先解决盾击基础，再处理十字，最后宽弧高速续段，控制适配复杂度 | 每人独立验收接近、普攻、强招、二阶段和输出窗口；不能只改强招留下无预警普攻 |
| E 施法、远程与指挥辨识 | 先保持赫兹/薇拉/赛芙琳合理机制，改源头和动作；再做伊诺/弥迦身份，最后亡军、凯恩与雷欧尼斯的召唤/指挥叠压 | 每人有两项非颜色识别特征，召唤有界，普通与复合路径独立验收 |
| F 组合体验与难度 | 多 Boss、残兵、地图和玩家特效叠加；六角色、元素、模块、成长和高难度一起验证 | 自动测试与真实渲染通过，人工自然流程能说明各角色解招与输出；参数调整有前后数据 |

A 阶段的区域范围修复会改变边缘位置的受伤行为，属于需要独立批准的玩法修复，不混在美术提交里。B/C 可以交替推进小样，但不能绕过 A 的接口、用户风格决策和范围契约。整合顺序是建议，不表示现在启动任何一阶段。

### 7.2 通用验收清单

| 维度 | 必须验证 | 通过标准 |
| --- | --- | --- |
| 状态与边界 | 15/30/60/120 FPS，零 dt，双阶段，连段、跨步/冲锋，状态效果、死亡、重置与阶段打断 | 时序一致、关键字段有限、每段最多一次伤害；不隧穿，不续接已取消招，不丢施法令牌；冻结暂停的状态表现一致 |
| 几何 | 范围内/外、边线两侧、侧后方、离开锁定区、世界边角、障碍、分离推挤 | 同一形状驱动显示与判定；既定中心/圆碰撞口径一致；可见安全区能通过实际路线到达 |
| 视觉 | 实际游戏缩放、宽窄视口、左右/上下/斜向、位图缺失/慢载/坏帧、受击/阶段叠加 | 枪盾锤戟可辨；武器动作与结算时刻一致，脚底稳定；回退不改规则；危险预警不被遮住 |
| 六角色基础 | 固定等级、基因、技能、种子及路线，记录双方伤害、击杀耗时、有效输出时间、资源积累 | 各角色能靠普通移动解招并产生有效输出；暴食能形成积点循环，暗影不依赖赌闪避，共生能追上，元素毒素并非因位移完全失效 |
| 成长与构筑 | 火/冰/雷/毒及六种融合分批覆盖；伙伴单只/完整小队、射速/移速/范围成长、origin 不同专精 | 不强行等 DPS；无一类因状态接口失效而丧失功能，也不按角色 ID 偷改 Boss 抗性；高成长能更快结束战斗 |
| 多来源叠压 | 原有残兵、已有弹幕、Boss 编队、召唤上限、玩家高特效场景 | 不清空原战场来伪造公平；全场大预警维持调度；可读且有实际通路；召唤量和特效对象数量有界 |
| 自动化 | 针对变更专项、完整 `npm test`、`npm run build`；触及启动/资源加载时补 `npm run test:startup` | 在同一候选提交通过；不通过时停止该功能的集成，不以修改断言掩盖失败 |
| 人工体验 | 六角色至少完成一次基础流程；重点复测毒素、伙伴追击、近战积点、地图边角与二阶段 | 记录版本、难度、成长、路线、失败原因与体验意见；先形成参照，再定耗时范围，不凭本稿虚设统一秒数或胜率 |

边防官已有 25 秒脚本交战和六角色浏览器验证可作回归参照，但不是通关胜率、自然成长耗时或完整美术验收。移动端目前没有完整触控支持；可先验证窄视口与预警尺寸，触控体验应在输入适配具备后另验，不能声称已支持移动端。

每个后续提交须说明：改变哪一层（美术/动作/规则）、沿用哪条正式机制、抽取哪份候选、运行哪些验证及剩余人工风险。纯文档与不改规则的外形提交不需要重新跑全项目玩法测试；规则/接口修改必须按上表执行。
